# FL.ru Parser

Парсер и анализатор задач с фриланс-биржи [FL.ru](https://www.fl.ru).
Получает RSS-ленту, фильтрует по ключевым словам DevOps-тематики,
загружает полное описание каждой задачи со страницы FL.ru (JSON-LD),
анализирует через AI (OpenAI-совместимый API) и сохраняет в SQLite.

## Минимальные требования

- **Docker** и **Docker Compose** (сервер на Debian/Ubuntu) — для запуска в контейнере
- **Python 3.11+** — для локального запуска без Docker
- Стандартная библиотека Python: `sqlite3`, `urllib`, `xml.etree`, `json`, `argparse`, `html`, `re`


## Быстрый старт (локально)

```bash
cp example.env .env
# Отредактируйте .env — укажите FL_BOT_TOKEN, FL_CHAT_ID, FLRU_LLM_API_KEY и др.

python3 flparser.py              # Один проход: RSS → фильтр → AI → вывод в stdout
python3 flparser.py --dry-run    # Только фильтрация, без AI и записи в БД
python3 flparser.py --stats      # Показать статистику за всё время хранения
python3 flparser.py --stats-today  # Разбивка и топ за сегодня («Всего»/«За сегодня» — по всей БД)
```

При запуске без параметров скрипт выполняет один проход парсинга и завершается.

## Развёртывание через Docker Compose

### 1. Подготовка сервера

Нужны два файла: `docker-compose.yml` и `.env` (весь репозиторий не обязателен).

```bash
mkdir flparser && cd flparser
# Скопируйте docker-compose.yml и example.env из репозитория
cp example.env .env
# Заполните .env своими значениями

mkdir -p flparser_data
sudo chown 1000:1000 flparser_data
```

> **Важно:** контейнер работает от пользователя с UID 1000, а каталог `flparser_data`
> монтируется с хоста. Без `chown 1000:1000` приложение не сможет создать БД и лог
> и завершится с ошибкой.

Контейнер использует часовой пояс хоста (`/etc/localtime` и `/etc/timezone`).
Расписание cron работает по этому поясу, поэтому проверьте его командой `timedatectl`.

### 2. Запуск

```bash
docker compose pull      # Образ ghcr.io/ru-admin/flparser:latest (публичный, логин не нужен)
docker compose up -d
docker logs -f flparser
```

Обновление образа:

```bash
docker compose pull && docker compose up -d
```

### 3. Расписание

Расписание задаётся в `.env` в формате cron (минута час день месяц день_недели):

| Переменная   | Пример        | Что запускается                                    |
| ------------ | ------------- | -------------------------------------------------- |
| `CRON_PARSE` | `*/10 * * * *` | `/app/flparser` — один проход парсера             |
| `CRON_STATS` | `59 23 * * *`  | `/app/flparser --stats-today` — статистика за сегодня |

Статистика за всё время хранения: `docker exec flparser /app/flparser --stats`.

### 4. Как это работает

- `docker-entrypoint.sh` при старте контейнера:
  1. Выполняет `flparser --stats` как проверку конфигурации, БД и лога
     (с пустым `FL_BOT_TOKEN`, в Telegram ничего не отправляется).
     Если проверка не прошла, контейнер завершается с ошибкой — причина видна в `docker logs`.
  2. Генерирует crontab из `CRON_PARSE` и `CRON_STATS` и запускает
     [supercronic](https://github.com/aptible/supercronic) на переднем плане.
- Данные хранятся на хосте в каталоге `./flparser_data`, который монтируется в `/app/data`:
  - `flparser.db` — SQLite база данных;
  - `flparser.log` — лог приложения.

## Логика работы

1. Загрузка RSS-ленты FL.ru через `FL_PROXY`
2. Фильтрация: стоп-слова и ключевые слова ищутся по границам слов с учётом
   словоформ (русские окончания, латинские `s/es`), поэтому «реклама» отсекает
   «рекламы», а `api` не срабатывает внутри других слов. Задача проходит, только
   если найдено хотя бы одно **сильное** ключевое слово — конкретная технология
   или инструмент (`docker`, `kubernetes`, `terraform`, `mysql`, `1с-битрикс` и т.п.).
   Общие слова (`настройка`, `сервер`, `api`, `мониторинг`, `автоматизация`)
   сохраняются в `keywords_matched`, но сами по себе задачу не пропускают.
3. Дедупликация (проверка наличия в БД)
4. Для каждой подходящей задачи:
   - Загрузка полного описания со страницы задачи (JSON-LD)
   - AI-анализ через `AI_PROXY`
   - Запись в БД
5. Вывод результата в stdout и отправка в Telegram

## Раздельные прокси

| Переменная | Для чего                              |
| ---------- | ------------------------------------- |
| `FL_PROXY` | Только для RSS, страниц задач, urllib |
| `AI_PROXY` | Только для запросов к LLM             |
| `TG_PROXY` | Только для Telegram Bot API           |

Если переменная не задана — работаем напрямую.

## Конфигурация

Все настройки задаются через переменные окружения. Приоритет загрузки:
1. Переменные окружения процесса (в Docker — `environment` и `env_file` из compose)
2. `.env` в директории проекта
3. `/etc/flparser/env`

### Переменные окружения

#### Telegram
| Переменная     | По умолчанию | Описание                                                          |
| -------------- | ------------ | ----------------------------------------------------------------- |
| `FL_BOT_TOKEN` | *(пусто)*    | Токен Telegram-бота (alias: `FL_TELEGRAM_BOT_TOKEN` )             |
| `FL_CHAT_ID`   | *(пусто)*    | ID чата для отправки результатов (alias: `FL_TELEGRAM_CHAT_ID` )  |
| `TG_PROXY`     | *(пусто)*    | Прокси для Telegram Bot API (например, `http://127.0.0.1:18080` ) |

#### LLM API
| Переменная                      | По умолчанию               | Описание                                         |
| ------------------------------- | -------------------------- | ------------------------------------------------ |
| `FLRU_LLM_API_KEY`              | *(пусто)*                  | API-ключ для LLM (fallback на `OPENAI_API_KEY` ) |
| `FLRU_LLM_BASE_URL`             | *(пусто)*                  | Базовый URL OpenAI-совместимого API              |
| `FLRU_AI_MODEL`                 | *(пусто)*                  | Модель для анализа                               |
| `HERMES_OPENROUTER_APP_REFERER` | `https://github.com/ru-admin/flparser` | Referer для OpenRouter                |
| `HERMES_OPENROUTER_APP_TITLE`   | `FL.ru Parser`             | Title для OpenRouter                             |

#### Расписание (Docker)
| Переменная   | По умолчанию | Описание                                                        |
| ------------ | ------------ | --------------------------------------------------------------- |
| `CRON_PARSE` | *(обязательна)* | Расписание прохода парсера (формат cron)                     |
| `CRON_STATS` | *(обязательна)* | Расписание `--stats-today` (формат cron)                     |

#### Дебаг
| Переменная      | По умолчанию | Описание                                                       |
| --------------- | ------------ | -------------------------------------------------------------- |
| `FLRU_DEBUG2TG` | `false`      | Расширенный дебаг-блок в stdout + внешний IP через ifconfig.co |

#### Прокси
| Переменная | По умолчанию | Описание                              |
| ---------- | ------------ | ------------------------------------- |
| `FL_PROXY` | *(пусто)*    | Прокси для RSS, страниц задач, urllib |
| `AI_PROXY` | *(пусто)*    | Прокси для LLM API                    |

#### RSS и лимиты
| Переменная          | По умолчанию                    | Описание                            |
| ------------------- | ------------------------------- | ----------------------------------- |
| `FL_RU_RSS_URL`     | `https://www.fl.ru/rss/all.xml` | URL RSS-ленты FL.ru                 |
| `MAX_TASKS_PER_RUN` | `60`                            | Максимум задач за один запуск       |
| `REQUEST_TIMEOUT`   | `30`                            | Таймаут HTTP-запросов к FL.ru (сек) |
| `AI_TIMEOUT`        | `60`                            | Таймаут запросов к LLM API (сек)    |

#### Retry-политика
| Переменная  | По умолчанию | Описание                            |
| ----------- | ------------ | ----------------------------------- |
| `URL_RETRY` | `3`          | Количество попыток при ошибках сети |
| `URL_DELAY` | `2`          | Задержка между попытками (сек)      |

#### Приоритеты
| Переменная                  | По умолчанию | Описание                                |
| --------------------------- | ------------ | --------------------------------------- |
| `PRIORITY_HIGH_THRESHOLD`   | `80`         | Порог match_score для HIGH приоритета   |
| `PRIORITY_MEDIUM_THRESHOLD` | `60`         | Порог match_score для MEDIUM приоритета |

> **Важно:** Сложные структуры данных (`KEYWORDS`, `STOP_WORDS`, `AI_PROFILE`, `AI_PROMPT_TASK_ANALYSIS`) остаются в коде (`flparser.py`) и не вынесены в `.env`.

## База данных (SQLite)

- `processed_ids` — дедупликация (guid + время)
- `tasks` — задачи с AI-анализом
- Автоочистка записей старше 10 дней

Файл БД: `data/flparser.db` (локально), `./flparser_data/flparser.db` (Docker). Создаётся автоматически.

## Обработка ошибок

Все внешние вызовы используют retry:
- `URL_RETRY = 3` попытки
- `URL_DELAY = 2` секунды между попытками
- При 429 (rate limit) — экспоненциальная задержка
- Если AI-анализ не удался — задача пропускается, цикл продолжается

Ошибки доступа к логу или БД останавливают работу с сообщением `[FATAL]` и ненулевым кодом возврата.

## Логирование

- Файл: `data/flparser.log` (локально), `./flparser_data/flparser.log` (Docker)
- Формат: `YYYY-MM-DD HH:MM:SS message`
- Уровень: DEBUG
- Каждый прогон пишет в лог старт, счётчики `RSS/после фильтра/новых` и завершение — так
  видно, что расписание отработало, даже если новых задач не было

## Полезные команды

```bash
# Локально
./flparser --stats        # за всё время хранения (10 дней)
./flparser --stats-today  # только за сегодня
./flparser --dry-run      # тест без AI (проверка фильтрации)
tail -f data/flparser.log

# В Docker
docker exec flparser /app/flparser --stats
docker exec flparser /app/flparser --stats-today
docker exec flparser /app/flparser --dry-run
docker logs -f flparser
tail -f flparser_data/flparser.log
```
